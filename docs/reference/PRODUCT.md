# Nearby prototype

<!-- impeccable:product-schema 1 -->

## Platform
web

## Stack
User requested a standalone HTML prototype served on localhost. Inline CSS and JavaScript, without a build step or external dependencies. The eventual desktop application is a separate project.

## Users
Nontechnical people sharing information among 2–20 computers on a local network.

## Product Purpose
Automatically discover nearby app users and share text, links, and code in named rooms that everyone can see and post to.

## Operating Context
Desktop app intended for macOS, Linux, and Windows. Install, open, allow network access if prompted, and communicate. No accounts, joining codes, or network settings. Previous conversation answers already confirm these requirements.

## Capabilities and Constraints
Anyone creates rooms; only the creator renames or archives them. Missed messages synchronize when another device retaining them is available. Old network histories stay local when moving networks. Closing the window retains background reception; Quit stops the app. Prototype uses clearly identified sample people and messages and browser-local storage. It does not implement LAN networking. Initial scope is text, links, and code.

## Brand Commitments
User requested professional, minimal, memory-efficient, non-generic UI and delegated the recommended design. Nearby is an explicitly provisional name selected for this prototype. No existing assets or brand.

## Product Principles
Immediate discovery and minimal configuration. Reading, sending, and copying are primary. Familiar desktop interactions. Clear connection and delivery states.

## Evidence on Hand
Product requirements are confirmed in this conversation. All prototype people and message content are synthetic and labeled as sample content in the interface.
